# taskvim v0.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split `src/main.rs` into modules, fix two log-integrity bugs, add fixed Important/General/Agent sections to the dashboard, and add period-reset recurring tasks.

**Architecture:** Four phases in order. Phase 1 is pure code motion, guarded by characterization tests written *before* the split. Phase 2 fixes the log bugs by adding a `LogEntry.task` back-link. Phase 3 turns the flat dashboard list into interleaved section/task rows. Phase 4 adds habits that reset on a fixed calendar grid and never carry due dates.

**Tech Stack:** Rust 2021, ratatui 0.29, crossterm 0.28, serde/serde_json, chrono 0.4. Tests are stock `cargo test` with `#[cfg(test)] mod tests` blocks in the module under test — no new dependencies.

**Spec:** `docs/superpowers/specs/2026-08-26-taskvim-sections-recurring-design.md`

**Deviation from the spec, deliberate:** the spec put `due_span` in `due.rs`. `due_span` returns a ratatui `Span` and depends on the theme constants, so it belongs in the UI layer. `due.rs` stays pure (no ratatui import) and therefore stays easy to unit test. `due_span` moves to `src/ui/theme.rs`.

## File Structure

| File | Responsibility |
|---|---|
| `src/main.rs` | entry point, terminal setup, `run()` loop, module declarations |
| `src/model.rs` | `Task`, `Section`, `Project`, `LogEntry`, `DashSection`, `Repeat`, `RepeatUnit`, `Data` + load/save/sanitize/migrate |
| `src/due.rs` | `parse_due` and the recurrence grid math — pure, no ratatui |
| `src/parse.rs` | add-line parsing: `@course`, `!due`, `#section`, `~repeat` — pure |
| `src/app/mod.rs` | `App` struct, `Pane`/`View`/`Row`/`DashRow`/`InsertTarget`/`Mode`, undo/redo, lookups, stats |
| `src/app/actions.rs` | add / complete / delete / move / pin / priority / tick |
| `src/app/keys.rs` | `handle_key` and the per-view handlers, `run_command` |
| `src/ui/mod.rs` | `ui()` and top-level layout |
| `src/ui/theme.rs` | `PALETTE`, `ACCENT`, `DIM`, `SEL_BG`, `palette()`, `ellipsize()`, `due_span()`, `repeat_span()` |
| `src/ui/dashboard.rs` | dashboard layout, task sidebar, task lines, greeting |
| `src/ui/courses.rs` | course cards and the course modal |
| `src/ui/log.rs` | log and daylog views |
| `src/ui/heatmap.rs` | heatmap, daily goal, priority widget |
| `src/ui/help.rs` | help screen |
| `src/ui/popup.rs` | input popup, due menu, repeat menu, statusbar |

Inherent `impl App` blocks may live in any module of the same crate, so `App` is declared in `src/app/mod.rs` and its methods are split across `mod.rs`, `actions.rs`, and `keys.rs` without wrappers or traits.

    /// Dashboard rows in display order. `data.dashboard` remains the source of
    /// truth for task *order*; the section is a property of the task, so this
    /// walks the dashboard once per section and preserves relative order.
    /// Empty section headers are kept so 1/2/3 always have a visible target.
    pub fn dash_rows(&self) -> Vec<DashRow> {
        let visible = self.dash_ids();
        let mut rows = Vec::with_capacity(visible.len() + DashSection::ALL.len());
        for sec in DashSection::ALL {

            for id in &visible {

    /// Reorder the selected task among the siblings in its own section.
    /// Because `dash_rows()` groups by section, a task's section siblings are
    /// its adjacent `DashRow::Task` rows — a move that would cross a header is
    /// simply refused.
    pub fn move_dash_task(&mut self, delta: i32) {
        let rows = self.dash_rows();
        let Some(DashRow::Task(a_id)) = rows.get(self.task_sel).copied() else {
            return;
        };
        let target = self.task_sel as i32 + delta;
        if target < 0 || target as usize >= rows.len() {
            return;
        }
        let Some(DashRow::Task(b_id)) = rows.get(target as usize).copied() else {
            // Neighbour is a section header — we're at the edge of the section.
            return;
        };
        let a = self.data.dashboard.iter().position(|id| *id == a_id);
        let b = self.data.dashboard.iter().position(|id| *id == b_id);
        if let (Some(a), Some(b)) = (a, b) {
            self.data.dashboard.swap(a, b);
            self.task_sel = target as usize;
            self.save_quiet();
        }
    }

fn match_section(name: &str) -> Option<DashSection> {
    let n = name.trim().to_lowercase();
    if n.is_empty() {
        return None;
    }
    DashSection::ALL
        .into_iter()
        .find(|s| s.title().to_lowercase().starts_with(&n))

/// Strip trailing `!due`, `@course` and `#section` tokens in any order.
/// A token that doesn't resolve — an unknown course, an unparseable date, a
/// `#4` that isn't a section — is left in the text as literal content.
pub fn parse_task_input(projects: &[Project], buf: &str) -> ParsedTask {
    let mut text = buf.trim().to_string();
    let mut project = None;
    let mut due = None;
    let mut section = None;

    // One pass per possible token, plus one to settle.
    for _ in 0..4 {
        let before = text.clone();

        if due.is_none() {
            if let Some(tok) = text.split_whitespace().last() {
                if let Some(spec) = tok.strip_prefix('!') {
                    if let Ok(d) = parse_due(spec) {
                        due = d;
                        let cut = text.rfind('!').unwrap();
                        text = text[..cut].trim().to_string();
                    }
                }
            }
        }

        if section.is_none() {
            if let Some(tok) = text.split_whitespace().last() {
                if let Some(name) = tok.strip_prefix('#') {
                    if let Some(s) = match_section(name) {
                        section = Some(s);
                        let cut = text.rfind('#').unwrap();
                        text = text[..cut].trim().to_string();
                    }
                }
            }
        }

        if project.is_none() {
            if let Some(pos) = text.rfind('@') {
                let name = text[pos + 1..].trim().to_lowercase();
                if !name.is_empty() && pos > 0 {
                    if let Some(p) = projects
                        .iter()
                        .find(|p| p.name.to_lowercase().starts_with(&name))
                    {
                        project = Some(p.id);
                        text = text[..pos].trim().to_string();
                    }
                }
            }
        }

        if text == before {
            break;
        }
    }

    ParsedTask { text, project, due, section }
}

use crate::model::{Repeat, RepeatUnit};

/// Snap a date back to the start of its grid cell: the day itself, its Monday,
/// or the 1st of its month.
pub fn align(date: NaiveDate, unit: RepeatUnit) -> NaiveDate {
    match unit {
        RepeatUnit::Day => date,
        RepeatUnit::Week => {
            date - CDuration::days(date.weekday().num_days_from_monday() as i64)
        }
        RepeatUnit::Month => {
            NaiveDate::from_ymd_opt(date.year(), date.month(), 1).unwrap_or(date)
        }
    }
}

/// Whole grid cells from `base` to `target`. Both must already be aligned.
fn units_between(base: NaiveDate, target: NaiveDate, unit: RepeatUnit) -> i64 {
    match unit {
        RepeatUnit::Day => (target - base).num_days(),
        RepeatUnit::Week => (target - base).num_days() / 7,
        RepeatUnit::Month => {
            (target.year() as i64 - base.year() as i64) * 12
                + (target.month() as i64 - base.month() as i64)
        }
    }
}

fn add_units(base: NaiveDate, n: i64, unit: RepeatUnit) -> NaiveDate {
    match unit {
        RepeatUnit::Day => base + CDuration::days(n),
        RepeatUnit::Week => base + CDuration::days(n * 7),
        RepeatUnit::Month => {
            if n >= 0 {
                base.checked_add_months(Months::new(n as u32)).unwrap_or(base)
            } else {
                base.checked_sub_months(Months::new((-n) as u32)).unwrap_or(base)
            }
        }
    }
}

/// The start of the period `today` falls in, on the fixed grid defined by the
/// repeat's unit, stride and anchor. Ticks land here regardless of whether the
/// task was ever completed.
pub fn period_start(today: NaiveDate, repeat: &Repeat) -> NaiveDate {
    let anchor = NaiveDate::parse_from_str(&repeat.anchor, "%Y-%m-%d").unwrap_or(today);
    let base = align(anchor, repeat.unit);
    let target = align(today, repeat.unit);
    let every = repeat.every.max(1) as i64;
    // div_euclid floors toward negative infinity, so dates before the anchor
    // land on an earlier grid cell instead of rounding toward it.
    let steps = units_between(base, target, repeat.unit).div_euclid(every);
    add_units(base, steps * every, repeat.unit)
}

    /// Reset every habit whose period has rolled over. Pure state transition
    /// against an explicit date so it can be tested without waiting for
    /// midnight; `tick()` supplies today.
    ///
    /// Deliberately bypasses the undo stack: a rollover is not a user edit, so
    /// pressing `u` after midnight should undo your last real action.
    pub fn tick_on(&mut self, today: NaiveDate) -> bool {
        let mut changed = false;
        for t in self.data.tasks.iter_mut() {
            let Some(r) = t.repeat.as_ref() else { continue };
            let start = crate::due::period_start(today, r).format("%Y-%m-%d").to_string();
            if t.period.as_deref() != Some(start.as_str()) {
                t.period = Some(start);
                t.completed = false;
                // Habits never carry a due date; clear any left by an edit
                // that predates the repeat being set.
                t.due = None;
                changed = true;
            }
        }
        if changed {
            self.saved_snapshot = self.data.clone();
            let _ = self.data.save();
            self.clamp();
        }
        changed
    }

    /// Run the tick for today.
    pub fn tick(&mut self) -> bool {
        self.tick_on(Local::now().date_naive())
    }

```rust
/// Parse a repeat spec: `3d` · `2w` · `1mo` · `daily` · `weekly` · `monthly`
/// · `none`/`-`/`""` to clear. `anchor` is today's date in YYYY-MM-DD.
pub fn parse_repeat(spec: &str, anchor: &str) -> Result<Option<Repeat>, ()> {
    let s = spec.trim().to_lowercase();
    if s.is_empty() || s == "none" || s == "clear" || s == "-" {
        return Ok(None);
    }
    let mk = |every: u32, unit: RepeatUnit| {
        Ok(Some(Repeat { every, unit, anchor: anchor.to_string() }))
    };
    match s.as_str() {
        "daily" | "day" | "d" => return mk(1, RepeatUnit::Day),
        "weekly" | "week" | "w" => return mk(1, RepeatUnit::Week),
        "monthly" | "month" | "mo" | "m" => return mk(1, RepeatUnit::Month),
        _ => {}
    }
    let (num, unit) = if let Some(rest) = s.strip_suffix("mo") {
        (rest, RepeatUnit::Month)
    } else if let Some(rest) = s.strip_suffix('m') {
        (rest, RepeatUnit::Month)
    } else if let Some(rest) = s.strip_suffix('w') {
        (rest, RepeatUnit::Week)
    } else if let Some(rest) = s.strip_suffix('d') {
        (rest, RepeatUnit::Day)
    } else {
        (s.as_str(), RepeatUnit::Day)
    };
    let n: u32 = num.trim().parse().map_err(|_| ())?;
    if n == 0 {
        return Err(());
    }
    mk(n, unit)
}
```

## Notes for the implementer

**The data file is real.** `~/.local/share/taskvim/data.json` holds the user's actual tasks. Task 8 backs it up to `data.json.pre-v03`. If a migration goes wrong, restore from there.

**MANDATORY: isolate the data file.** `App::save_quiet` writes to `Data::path()`, and several tested methods call it — so `cargo test`, and any run of the binary, can write to the user's real `~/.local/share/taskvim/data.json`. **This already happened once during Phase 1: the live data file was overwritten with a months-old backup and had to be restored from `data.json.pre-v03`.**

`Data::path()` uses `dirs::data_dir()`, which honours `$XDG_DATA_HOME`. So isolation needs no code change — just always set it:

```bash
export XDG_DATA_HOME=/tmp/taskvim-scratch
cargo test          # writes to /tmp/taskvim-scratch/taskvim/data.json
cargo run --release # same
```

Every task from here on MUST run `cargo test` and the binary with `XDG_DATA_HOME` pointed at a scratch directory. Never run either against the default path. Verified working: with `XDG_DATA_HOME` set, a full app run wrote nothing to the real location.

To smoke-test against realistic data, copy the real file into the scratch dir first — never point the app at the original.

**Line numbers drift.** Every line reference in Phase 1 is against the original 2845-line `src/main.rs` at commit `447a6be`. After the first move task they're stale — locate code by function name from then on.

**Row indices in tests.** `dash_rows()` always emits three headers, so with tasks in General the row indices are: 0 Important, 1 General, 2 first General task. Off-by-one errors here are the most likely source of a confusing test failure.
